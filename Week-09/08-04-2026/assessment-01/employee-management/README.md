A full-featured Employee Management Dashboard built with **React** and **Redux Toolkit**, demonstrating enterprise-level state management patterns including role-based access control, middleware, and localStorage persistence.

---

## Features

### Core Redux Concepts Demonstrated
- **Store** — Single source of truth via `configureStore`
- **Actions** — Auto-generated via `createSlice`
- **Reducers** — Immutable state updates using Immer (built into Redux Toolkit)
- **Middleware** — `redux-logger` logs every dispatched action to the browser console
- **State Persistence** — `localStorage` save/load on every store update
- **Provider** — Wraps the entire app so all components access the store

### Application Features
- Role-based access control (Admin vs HR Manager)
- Employee CRUD — Add, Edit, Delete, Search, Filter
- Global UI state — Dark/Light mode toggle
- Loading spinner component
- Toast notifications
- Department breakdown analytics (Admin only)
- Responsive layout

## Redux Data Flow

```
Component
   │
   │  dispatch(action)
   ▼
Action Creator (createSlice)
   │
   ▼
Reducer (pure function, Immer immutability)
   │
   ▼
Store (single source of truth)
   │
   │  useSelector
   ▼
UI Re-renders
```

## Key Redux Concepts Covered (Assessment Tasks)

### Task 1 — What is Redux?
Redux is a **predictable state container** for JavaScript apps. All state lives in one place (the store), state can only change through dispatched actions, and reducers are pure functions — given the same input, they always return the same output. This makes debugging and testing straightforward.

**When NOT to use Redux:** Small apps with only local UI state, forms, or simple toggles that don't need to be shared across the component tree.

### Task 2 — Store, Actions, Reducers
- **Store** (`store.js`) — Holds the entire application state tree. Created once with `configureStore`.
- **Actions** — Plain JS objects like `{ type: 'employees/addEmployee', payload: {...} }`, auto-generated by `createSlice`.
- **Reducers** — Pure functions in each slice that describe how state changes in response to an action.

### Task 3 — Immutability
State must never be directly mutated. Redux Toolkit uses **Immer** internally, which lets you write what looks like mutating code (`state.list.push(item)`) but actually produces a new immutable state object under the hood.

### Task 4 — Data Flow Cycle
1. User clicks "Add Employee" → component calls `dispatch(addEmployee(data))`
2. Action travels to the `employees` reducer
3. Reducer returns a new state object with the employee added
4. Store updates with the new state
5. All components subscribed via `useSelector` re-render with the latest data

### Task 5 — Reducer Example
See `employeeSlice.js` — `addEmployee`, `updateEmployee`, `deleteEmployee` reducers each handle a single action type cleanly.
